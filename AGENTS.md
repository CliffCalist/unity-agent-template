# Unity Project Instructions

Before starting work, read the convention relevant to the task:

- [Unity Project File Organization](conventions/unity-project-organization.md) covers asset and GameObject naming, feature and shared asset folders, and scene and script placement. Use it when creating, moving, renaming, or organizing these files, folders, or GameObjects.
- [Unity Asset Migration](conventions/unity-asset-migration.md) defines the approval, planning, renaming, moving, and validation workflow for migrating assets to the project file organization convention. Use it together with the organization convention when migrating existing assets.
- [C# Code Style for Unity](conventions/unity-csharp-conventions.md) covers naming, attribute formatting, member order and semantic grouping, regions, and Unity lifecycle methods. Use this convention when writing or changing C# scripts or organizing their code.
- [Unity User Documentation](conventions/unity-user-documentation.md) defines manuals and system references for Unity users who do not read code. It covers material organization, Google writing guidance, Inspector descriptions, illustrations, and verification. Use it when creating or updating user-facing documentation.

If a task spans multiple areas, read and apply each relevant convention.

Apply the rules only within the scope of the task. Do not rename or restructure unrelated parts of an existing project solely to match the template. Explicit user requirements and project-specific rules take precedence.
